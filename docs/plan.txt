Implementation Guide: House Phone

This guide tracks the phased roadmap for House Phone, a pivot of the
original "Jarvis Edge Node" project (see docs/new_idea.txt for the pivot
proposal, docs/sdd.txt for the resulting system design).

Phases 1-6 below (hardware baseline through JARVIS 3.0 integration) are the
Jarvis Edge Node foundation the pivot builds on top of — all implemented,
kept mostly as-is. Phases 7-9 are the House Phone-specific work.

Phase 1: Hardware Baseline & UI Shell — done

ILI9488 + GT911 touch bring-up (LovyanGFX), LVGL v9 UI shell, the
persistent status bar + swipeable `lv_tileview` carousel.

Phase 2: Audio & Offline Mode (the "Plaud" feature) — done

SD-backed `/queue`, I2S PDM mic capture (buffered fully in PSRAM — the mic
and SD card share hardware and can't run simultaneously), BOOT-button
screen-off recording.

Phase 3: Backend API & AI Routing — done

FastAPI + SQLite, `POST /upload/audio` (multipart WAV), local faster-whisper
transcription, fast/heavy dual-tier Ollama routing.

Phase 4: Synchronization & MQTT — done

Mosquitto broker, ESP32 WiFi + PubSubClient, background auto-sync of
`/queue/*.wav`, MQTT push-back updating the Jarvis Voice Capture tile.

Phase 5: Command Center (Vite frontend) & On-device Settings — done

Vite + React admin frontend; on-device Settings tile (WiFi/backend/MQTT,
persisted to SD).

Phase 6: Full CRUD & JARVIS 3.0 integration — done

Backend CRUD for to-do items, optional best-effort bridge to a full
JARVIS 3.0 instance (voice transcripts delegated to its agent loop).

Phase 7: House Phone pivot — Ambient Home (Tapo) — done

Goal: control Tapo smart bulbs from the device without hand-rolling the
KLAP local protocol in firmware.

- Backend: `app/tapo.py` wraps `python-kasa` for local bulb control;
  `TapoZone` model + `/tapo/zones*` CRUD/toggle/brightness/all_off
  endpoints. Requires a Tapo account email/password in `config.yaml`.
- Firmware: `tapo_control.h/.cpp` polls `/tapo/zones` and posts
  toggle/brightness fire-and-forget; `ui_screen_home.h/.cpp` renders the
  Ambient Home grid (tap to toggle, long-press for brightness, "All Off").
- Frontend: `TapoPage.jsx` — zone CRUD, live toggle/brightness, All Off.

Phase 8: House Phone pivot — Landline Feed (BLE) — done

Goal: relay Android notifications from a paired phone without writing an
Android app.

- Firmware: `ble_notifications.h/.cpp` — a BLE GATT server (advertises as
  "House Phone") that accepts a JSON notification payload from a Tasker
  profile (BLE/GATT plugin) and holds the last few in an in-RAM ring
  buffer (never persisted — matches a real phone's ephemeral notification
  shade). `ui_screen_landline.h/.cpp` renders them as dismissible cards.
- Mobile side: configure Tasker with a BLE/GATT write plugin pointed at the
  characteristic UUID documented in `ble_notifications.h`; no custom app.

Phase 9: House Phone pivot — Timers & Alarms — done

Goal: a standalone bedside alarm clock + kitchen timer, no phone required.

- Firmware: `timers_alarms.h/.cpp` — non-blocking countdown timer (preset
  buttons) and a wall-clock alarm (compared against NTP-synced local time),
  both driving the onboard buzzer; persisted alarm hour/minute/enabled via
  `settings.h`. `ui_screen_timers.h/.cpp` renders presets, the countdown,
  and hour/minute rollers for the alarm.
- Hardware caveat: `TIMER_BUZZER_PIN` has not been confirmed against a real
  board revision — verify before flashing.

Phase 10: Cleanup — done

Removed the Daily Focus/Action Grid on-device tiles and their MQTT
push-back (replaced by Ambient Home / Landline Feed / Timers & Alarms in
the carousel); the backend's to-do CRUD moved to being Command-Center-only
(`TodoPage.jsx`, still fed by the heavy LLM tier's task extraction).

Not yet implemented (future work, not required for the pivot)

- Direct smart-light control from Landline Feed notifications (e.g. "turn
  off the lights" voice command routed to `/tapo/zones/all_off`).
- BLE-side acknowledgement back to Tasker (e.g. marking a notification read
  on the phone when dismissed on-device).
